# JOBO 视图人工验收

这是一份供用户复测的人工验收清单；已完成的隔离浏览器验证列在末尾，未列明的步骤仍待测试。单元测试和构建结果不能替代实际操作。

## 启动与进入

1. 双击工作树根目录的 `jobo-view-start-dev.bat`：
   `D:\PycharmProjects\DayGlanceJobo-view\jobo-view-start-dev.bat`。
2. 保持启动窗口打开，在浏览器访问 <http://127.0.0.1:5187/>。启动器固定使用 5187；若提示端口占用，先核对已运行的服务，不要把其他分支的页面当作本轮版本。
   代码修改后在 5187 页面刷新即可复测；服务仍在运行时不需要重启启动器。
3. 在设置的“实验性功能”中开启“JOBO 视图”；如果本设备的视图列表里隐藏了 JOBO，也要将它显示出来。
4. 使用桌面浏览器，将窗口拉宽到能显示完整视图切换入口。沿用 main 的入口条件是非手机、非平板且原生布局达到三日宽度；窄窗口下可能没有 JOBO，也不会响应快捷键 `6`。可以先使用最大化的宽桌面窗口。
5. 关闭设置，离开输入框后按 `6`，或从视图切换入口选 JOBO。**三日宽度是入口条件；JOBO 本身显示所选的一天。**
6. “全天 / 笔记”和缩放控件位于日期右侧，原独立提示行已移除。左右拖动时间轴或表头的握柄，调整 Plan 与 Do 的宽度；双击居中。时间轴获得键盘焦点后，左右方向键调整，Home 居中，拖动时 Esc 取消。
7. 选择测试日期，准备两个当天的普通定时任务 A、B，以及一个重复任务实例 C。使用容易辨认的测试标题。需要核对记录 ID 时，比较操作前后正常导出备份中的 `joboRecords`，不要只凭相同标题判断是否为同一条记录。

## 1. Plan 沿用原生任务操作

- [ ] 点击 Plan 栏的 `+`，以及 Plan 时间轴的空白位置：都打开原生新增任务编辑器；日期、开始时间对应所选位置。
- [ ] 双击任务 A 的 Plan 卡片，或点击铅笔：打开原生编辑器。修改标题、开始时间和时长，保存后核对原生日视图中的同一任务。
- [ ] 将 A 在 Plan 栏内上下拖动：原生任务时间随之改变，刷新后保持；没有额外创建 Do。
- [ ] **Plan 时长通过原生编辑器修改。** Plan 卡片不提供 Do 式的上下边缘缩放。
- [ ] 点击 B 的 Plan 完成框：原生任务变为完成；Slice 4 生成一条 `source: completion`、`progress: completed` 的 Untimed（“未计时”）记录，不能凭计划时长自动推断实际区间。
- [ ] 若完成记录没有出现在当前日期，按该完成时间戳的日期查看；完成记录日期不是强行套用 Plan 日期。

## 2. Plan 拖入 Do 与手动记录

- [ ] 将尚未完成的 A 从 Plan 拖到 Do 时间轴：新增一条手动 Do，初始进度为 `started`（“已开始”），与 A 关联并捕获当时的计划。
- [ ] A 的原生时间、时长和完成框不因这次拖放而改变。新 Do 的开始位置对应落点，初始时长沿用所拖计划。
- [ ] 点击 Do 栏的 `+`，以及 Do 时间轴空白位置：填写标题与完整实际区间后可新增独立手动 Do，默认“已开始”，不会新增或完成原生任务。
- [ ] 新记录保存后刷新，核对其位置、标题和进度仍在。

## 3. Do 移动、缩放与补录

- [ ] 上下拖动 A 的 timed Do：开始和结束一起平移，实际时长不变，Plan 不移动。
- [ ] 分别拉动 Do 顶部、底部边缘：只修改对应起止时间，另一端保持；不能缩成零长度或反向区间。边缘获得键盘焦点后，方向键上下按 5 分钟调整。
- [ ] 开始边缘拖动后按 `Esc`：取消本次预览，原记录不变。
- [ ] 双击 Do 或点铅笔，修改日期、开始时间、结束日期和结束时间；验证跨午夜记录在相邻日期按实际覆盖区间显示，历史标题仍不可编辑。
- [ ] 在 B 的 Untimed 记录上点编辑，选择“已计时”并填写实际区间，保存后移到时间轴。也测试将 Untimed 拖到时间轴，再在弹窗里确认区间。
- [ ] 补录后的 B 保留原 ID、来源、捕获标题、`planSnapshot` 和创建时间；只更新允许修正的区间/版本字段。它是同一条完成记录，不应复制出第二条 attempt。
- [ ] 填写缺失、倒置或无效的时间后尝试保存：显示错误并保留可继续编辑的弹窗，不写入坏区间。

## 4. 进度、重开与再次完成

- [ ] 打开手动 Do 编辑器，在进度下拉框依次选择“已开始 / 部分完成 / 大部分完成”，刷新后保持；原生任务 A 的完成框不跟着改变。
- [ ] Do 卡片仅展示标题、实际区间与时长；Plan 卡片只展示按 `createdAt` 判定的最近一次进度。打开执行详情后查看完整 attempt 历史；修改旧 attempt 的 `updatedAt` 不应改变最近一次排序。没有关联 Plan 的手动 Do 仍可在详情中查看和修改进度。
- [ ] Do 编辑器不提供把普通手动记录直接提升为“已完成”的路径。“已完成”来自原生任务完成事件；已有 completed 记录可保留现状或重新评估为前三种进度。
- [ ] 重新打开 B 的原生任务（取消 Plan 完成框）：此前完成生成的那条 Do 变为 `partial`，保留原 ID、补录区间及捕获计划。
- [ ] 再次完成 B：原任务再次完成，并追加一个新 ID 的 completed、Untimed attempt；上一个 partial attempt 仍然保留。
- [ ] 对重复任务 C 的同一天实例重复“完成 → 重开 → 再次完成”：确认同日出现新的 attempt，而其他日期的重复实例不被改动或错误并入“分段”。

## 5. 捕获快照与关联显示

- [ ] A 已有 Do 后，通过原生编辑器重命名 A：Do 与捕获 Plan 继续展示创建时标题；再次打开仍对应当前原生任务，不能把旧标题写回当前任务。
- [ ] 再把 A 的原生计划移到另一个时间：旧 captured Plan 保持原位置并标为“历史计划”，新的当前 Plan 显示新位置。
- [ ] 历史 Plan 没有原生完成、编辑或拖动能力；已有 Do 仍可修正实际区间，但不能改写捕获计划。
- [ ] 删除一个专门用于此项的原生测试任务：它已有的 captured Plan 和 Do 仍可阅读，历史 Plan 不产生可操作的假任务。
- [ ] 悬停有关联的 Plan、Do、备注：连接线指向对应分组；同一任务不同捕获计划的 Do 不应连到错误的当前 Plan。

## 6. 删除 Do 与原生备注

- [ ] 打开一条专用测试 Do，在编辑器中点“删除”：记录从活动视图消失，原生任务与其他 attempts 保留，刷新后不会重现。备份核对时应保留同 ID 的 `deleted: true` 墓碑，而不是抹掉历史。
- [ ] 展开工具栏“备注”，编辑当天备注，保存后在原生日视图查看同一天的内容，再回 JOBO 核对。
- [ ] 编辑任务 A 的备注，保存后打开原生任务核对同一内容；取消编辑不写入修改。JOBO 没有另外创建一套任务备注。
- [ ] 备注来自当前原生任务；历史 Plan/Do 的捕获标题与计划不因备注编辑而改变。导入项目是否可写遵循原生限制。

## 需要保持的 Slice 4 语义

| 操作 | 应保留的规则 |
| --- | --- |
| 原生完成 | 生成 completed、Untimed；完成勾选只证明发生过，不证明实际起止时间。 |
| 补录实际时间 | 更新同一个 ID，不追加完成记录。 |
| 原生重开、再次完成 | 旧 attempt 改为 partial；再次完成追加新 attempt。 |
| 改 Do 进度、时间或删除 Do | 不反向完成、重开或删除原生任务。 |
| 创建后的 title / planSnapshot | 捕获一次；不随原生任务重命名、改期或删除而刷新。 |
| `planSnapshot: null` | 确实没有 timed Plan，例如全天任务；不是未知历史的占位符。 |
| Plan 时间与时长 | 复用原生任务路径；时长从原生编辑器修改。 |
| “无 Do 记录” | 表示没有记录到执行，不证明用户实际上没有做。 |

契约依据：[ledger 与 Slice 4](jobo-ledger-persistence.md)、[core](jobo-core.md)。
